kavram Shell vs Environment Variables — İki değişken türü— Zwei Arten von Variablen

A shell variable only exists in your current terminal session. An environment variable is available system-wide, even to programs you launch from that shell.

TRShell değişkeni sadece şu an içinde bulunduğun terminal oturumunda vardır — terminali kapatınca kaybolur. Ortam (environment) değişkeni ise sistem genelinde geçerlidir, o terminalden başlattığın diğer programlar da bu değişkeni görebilir.

DEEine Shell-Variable existiert nur in deiner aktuellen Terminal-Sitzung — sie verschwindet, wenn du das Terminal schließt. Eine Umgebungsvariable gilt hingegen systemweit; auch Programme, die du aus dieser Shell startest, können sie sehen.

A variable name may only contain letters, numbers, and underscore (_), and must start with a letter or underscore. There must be no spaces around the = sign.

TRBir değişken adı sadece harf, rakam ve alt çizgi (_) içerebilir, ve harf veya alt çizgi ile başlamalıdır. = işaretinin etrafında boşluk olmamalıdır.

DEEin Variablenname darf nur Buchstaben, Zahlen und Unterstriche (_) enthalten und muss mit einem Buchstaben oder Unterstrich beginnen. Um das =-Zeichen dürfen keine Leerzeichen stehen.

✅ Valid❌ Invalid — why
KEY=value3_KEY=value — starts with a digit
_VAR=5-VAR=5 — hyphen (-) is a special character
LINUX_way=testLINUX-way=test — names can't contain a hyphen
✅ Geçerli❌ Geçersiz — neden
KEY=value3_KEY=value — rakamla başlıyor
_VAR=5-VAR=5 — tire (-) özel bir karakter
LINUX_way=testLINUX-way=test — isimde tire olamaz
✅ Gültig❌ Ungültig — warum
KEY=value3_KEY=value — beginnt mit einer Ziffer
_VAR=5-VAR=5 — Bindestrich (-) ist ein Sonderzeichen
LINUX_way=testLINUX-way=test — Namen dürfen keinen Bindestrich enthalten
💡 Tip: By convention (not required, but customary), environment variables are written in UPPERCASE: PATH, HOME, USER, etc.
💡 İpucu: Konvansiyon (zorunlu değil ama gelenek) olarak ortam değişkenleri BÜYÜK_HARF ile yazılır: PATH, HOME, USER gibi.
💡 Hinweis: Konventionell (nicht zwingend, aber üblich) werden Umgebungsvariablen in GROSSBUCHSTABEN geschrieben: PATH, HOME, USER usw.

path The PATH Variable — PATH değişkeni— Die PATH-Variable

Why can you type ls instead of /bin/ls? Because the shell checks each directory listed in PATH, in order, and runs the first matching executable it finds.

TRls yazdığında neden tam yolu (/bin/ls) yazmana gerek kalmıyor? Çünkü shell, PATH değişkeninde listelenen klasörleri sırayla kontrol eder ve ilk bulduğu eşleşen çalıştırılabilir dosyayı çalıştırır.

DEWarum kannst du ls statt /bin/ls eingeben? Weil die Shell die in PATH aufgeführten Verzeichnisse der Reihe nach prüft und die erste passende ausführbare Datei ausführt, die sie findet.

The shell tries each folder in PATH in order, stopping at the first match
Shell, PATH'teki klasörleri sırayla dener, ilk eşleşmede durur
Die Shell probiert die Ordner in PATH der Reihe nach aus und stoppt beim ersten Treffer
TERMİNALDE ÇALIŞTIR
printenv PATH
# örnek çıktı: /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
export PATH=$PATH:/home/ec2-user/test   # PATH'e yeni bir klasör ekle
💡 Tip: If you want to run a script you wrote from anywhere without typing ./, you need to add the folder it's in to PATH.
💡 İpucu: Kendi yazdığın bir scripti her yerden ./ yazmadan çalıştırmak istiyorsan, scriptin bulunduğu klasörü PATH'e eklemen gerekir.
💡 Hinweis: Wenn du ein selbst geschriebenes Skript von überall aus ausführen willst, ohne ./ einzutippen, musst du den Ordner, in dem es liegt, zu PATH hinzufügen.

quoting Quoting with Variables — Tırnak kullanımı— Anführungszeichen verwenden

Quoting controls whether the shell expands (substitutes the value of) a variable.

TRTırnak kullanımı, shell'in bir değişkeni genişletip genişletmeyeceğini (değerini yerine koyup koymayacağını) belirler.

DEAnführungszeichen bestimmen, ob die Shell eine Variable expandiert (ihren Wert einsetzt) oder nicht.

TypeBehaviorExample
Double quotes " "Expands variables, preserves everything except $ ' " \echo "$SHELL" → /bin/bash
Single quotes ' 'Expands nothing, preserves everything literallyecho '$SHELL' → $SHELL (literally)
Backslash \Escapes the next character, cancelling its special meaningecho "hello \$MYNAME" → hello $MYNAME
TürDavranışÖrnek
Çift tırnak " "Değişkenleri genişletir (expand eder), $ ' " \ hariç her şeyi korurecho "$SHELL" → /bin/bash
Tek tırnak ' 'Hiçbir şeyi genişletmez, her şeyi olduğu gibi korurecho '$SHELL' → $SHELL (harfiyen)
Ters bölü \Bir sonraki karakteri kaçırır (escape), özel anlamını iptal ederecho "hello \$MYNAME" → hello $MYNAME
TypVerhaltenBeispiel
Doppelte Anführungszeichen " "Expandiert Variablen, bewahrt alles außer $ ' " \echo "$SHELL" → /bin/bash
Einfache Anführungszeichen ' 'Expandiert nichts, bewahrt alles wörtlichecho '$SHELL' → $SHELL (wörtlich)
Backslash \Escaped das nächste Zeichen, hebt seine besondere Bedeutung aufecho "hello \$MYNAME" → hello $MYNAME
TERMİNALDE ÇALIŞTIR
MYNAME="james"
MYVAR="hello $MYNAME"
echo $MYVAR         # → hello james (çift tırnak: değişken genişler)
echo '$MYNAME'      # → $MYNAME (tek tırnak: hiç genişlemez)

sudo The sudo Command — sudo komutu— der sudo-Befehl

sudo ("superuser do") temporarily grants admin (root) privileges to a normal user for a single command.

TRsudo ("superuser do" — süper kullanıcı olarak yap), normal bir kullanıcıya, tek bir komut için geçici olarak yönetici (root) yetkisi verir.

DEsudo ("superuser do") gewährt einem normalen Benutzer vorübergehend Administratorrechte (root) für einen einzelnen Befehl.

TERMİNALDE ÇALIŞTIR
sudo yum update    # yönetici yetkisiyle sistemi güncelle
sudo su            # root kullanıcıya geç
sudo su -          # root'a, root'un kendi ortam ayarlarıyla birlikte geç
exit               # root'tan çık, önceki kullanıcına dön
💡 Tip: If you see # at the end of the prompt, you're now root — be very careful, root can delete/change anything.
💡 İpucu: Prompt sonunda # görüyorsan artık root'sundur — çok dikkatli ol, root her şeyi silebilir/değiştirebilir.
💡 Hinweis: Wenn du am Ende der Eingabeaufforderung # siehst, bist du jetzt root — sei sehr vorsichtig, root kann alles löschen/ändern.

kalıcılık Making Variables Permanent: Startup Files — Değişkenleri kalıcı yapmak— Variablen dauerhaft machen

An export only lives until you close the terminal. To make a setting permanent, it must be written into a startup file — a script the shell reads every time it starts. Which file runs depends on the shell type.

TRBir export yalnızca terminali kapatana kadar yaşar. Bir ayarı kalıcı yapmak için, shell'in her başladığında okuduğu bir başlangıç dosyasına yazılması gerekir. Hangi dosyanın çalışacağı shell türüne bağlıdır.

DEEin export lebt nur, bis du das Terminal schließt. Um eine Einstellung dauerhaft zu machen, muss sie in eine Startdatei geschrieben werden — ein Skript, das die Shell bei jedem Start liest. Welche Datei läuft, hängt vom Shell-Typ ab.

FileScopeWhen it runs
/etc/environmentSystem-wideSimple KEY=VALUE lines, read at login
/etc/profileSystem-wideEvery user's login shell
~/.profile / ~/.bash_profileOne userThat user's login shell
~/.bashrcOne userEvery interactive shell (each new terminal tab)
DosyaKapsamNe zaman çalışır
/etc/environmentSistem geneliBasit KEY=VALUE satırları, girişte okunur
/etc/profileSistem geneliHer kullanıcının login shell'i
~/.profile / ~/.bash_profileTek kullanıcıO kullanıcının login shell'i
~/.bashrcTek kullanıcıHer etkileşimli shell (her yeni terminal sekmesi)
DateiGeltungsbereichWann sie läuft
/etc/environmentSystemweitEinfache KEY=VALUE-Zeilen, beim Login gelesen
/etc/profileSystemweitDie Login-Shell jedes Benutzers
~/.profile / ~/.bash_profileEin BenutzerDie Login-Shell dieses Benutzers
~/.bashrcEin BenutzerJede interaktive Shell (jeder neue Terminal-Tab)
GERÇEK LINUX'TA — SİMÜLASYONDA YOK
echo 'export PATH=$PATH:$HOME/scripts' >> ~/.bashrc   # kalıcı PATH eki
source ~/.bashrc          # dosyayı yeniden yükle — yeni terminal açmadan uygula
💡 Tip: Golden rule: personal tweaks go in ~/.bashrc; machine-wide settings for all users go in /etc/environment. Never edit system files without a backup.
💡 İpucu: Altın kural: kişisel ayarlar ~/.bashrc'ye; tüm kullanıcılar için makine geneli ayarlar /etc/environment'a. Sistem dosyalarını asla yedeksiz düzenleme.
💡 Hinweis: Goldene Regel: Persönliche Anpassungen kommen in ~/.bashrc; maschinenweite Einstellungen für alle Benutzer in /etc/environment. Bearbeite Systemdateien nie ohne Backup.

expansion Parameter Expansion: Smart Defaults — Parametre genişletme— Parameter-Expansion

Bash can react to a variable being unset or empty right inside the ${ } syntax. These four patterns turn fragile scripts into robust ones — you'll meet them constantly in real-world DevOps scripts.

TRBash, bir değişkenin tanımsız ya da boş olmasına doğrudan ${ } sözdiziminin içinde tepki verebilir. Bu dört desen, kırılgan scriptleri sağlam scriptlere dönüştürür — gerçek dünyadaki DevOps scriptlerinde bunlarla sürekli karşılaşacaksın.

DEBash kann direkt innerhalb der ${ }-Syntax darauf reagieren, dass eine Variable nicht gesetzt oder leer ist. Diese vier Muster machen aus fragilen Skripten robuste — in echten DevOps-Skripten begegnen sie dir ständig.

SyntaxMeaning
${VAR:-default}Use default if VAR is unset/empty (VAR stays unchanged)
${VAR:=default}Use default AND assign it to VAR
${VAR:+alt}Use alt only if VAR IS set (else empty)
${VAR:?message}Abort with message if VAR is unset/empty
SözdizimiAnlamı
${VAR:-default}VAR tanımsız/boşsa default kullan (VAR değişmez)
${VAR:=default}default kullan VE VAR'a ata
${VAR:+alt}Yalnızca VAR tanımlıysa alt kullan (yoksa boş)
${VAR:?mesaj}VAR tanımsız/boşsa mesaj ile iptal et
SyntaxBedeutung
${VAR:-default}Nutze default, wenn VAR nicht gesetzt/leer ist (VAR bleibt unverändert)
${VAR:=default}Nutze default UND weise es VAR zu
${VAR:+alt}Nutze alt nur, wenn VAR gesetzt IST (sonst leer)
${VAR:?meldung}Bricht mit meldung ab, wenn VAR nicht gesetzt/leer ist
GERÇEK LINUX'TA — SİMÜLASYONDA YOK
echo "Rapor dizini: ${RAPOR_DIR:-/tmp/raporlar}"  # tanımsızsa varsayılanı bas
: "${API_KEY:?API_KEY tanımlı olmalı!}"           # güvenlik kapısı: yoksa dur
💡 Tip: The ${VAR:?} guard at the top of a deployment script is a professional habit: fail loudly at second 0 instead of mysteriously at minute 20.
💡 İpucu: Bir deployment scriptinin başındaki ${VAR:?} koruması profesyonel bir alışkanlıktır: 20. dakikada gizemli biçimde değil, 0. saniyede gürültüyle dur.
💡 Hinweis: Der ${VAR:?}-Schutz am Anfang eines Deployment-Skripts ist eine professionelle Gewohnheit: Lieber laut in Sekunde 0 scheitern als mysteriös in Minute 20.
