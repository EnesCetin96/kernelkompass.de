script Your First Script — İlk scriptin— Dein erstes Skript

A shell script is just a text file full of commands, run all at once. The first line — the shebang #!/bin/bash — tells the system which interpreter to use.

TRBir shell script'i, tek seferde çalıştırılan komutlarla dolu bir metin dosyasından ibarettir. İlk satır — shebang denen #!/bin/bash — sisteme "bu dosyayı bash ile çalıştır" der. "Shebang" adı, # (hash) + ! (bang) harflerinden gelir.

DEEin Shell-Skript ist einfach eine Textdatei voller Befehle, die alle auf einmal ausgeführt werden. Die erste Zeile — der Shebang #!/bin/bash — sagt dem System, welchen Interpreter es verwenden soll. Der Name "Shebang" kommt von # (hash) + ! (bang).

echo "Hello World"

./basic.sh          # çalıştır — "./" bulunduğun klasörden çalıştır demektir
💡 Tip: If you type it without ./ (basic.sh), the shell only searches the folders in PATH and won't find it. ./ means "look in the current folder".
💡 İpucu: ./ olmadan yazarsan (basic.sh), shell dosyayı sadece PATH'teki klasörlerde arar ve bulamaz. ./ "bulunduğun klasörde ara" demektir.
💡 Hinweis: Wenn du es ohne ./ schreibst (basic.sh), sucht die Shell nur in den Ordnern in PATH und findet es nicht. ./ bedeutet "im aktuellen Ordner suchen".

yorum Comments & Heredoc — Yorum satırları ve Heredoc— Kommentare und Heredoc

Bash ignores everything after # (except the shebang's first line). Bash has no native multi-line comment — but a heredoc block can serve as one.

TRBash, #'den sonraki her şeyi yok sayar (ilk satırdaki shebang hariç). Bash'te çok satırlı yorum diye bir şey yoktur — ama bir heredoc bloğu bu işi görebilir.

DEBash ignoriert alles nach # (außer der Shebang-Zeile). Bash hat keinen nativen mehrzeiligen Kommentar — aber ein Heredoc-Block kann diese Rolle übernehmen.

değişken Variables & Command Substitution — Değişkenler ve komut yerine koyma— Variablen und Befehlssubstitution

Command substitution captures a command's output and stores it as a variable's value, using $(...) or backticks.

TRCommand substitution (komut yerine koyma), bir komutun çıktısını alıp bir değişkene atamanı sağlar — $(...) veya backtick (`) ile yapılır.

DEBefehlssubstitution erfasst die Ausgabe eines Befehls und speichert sie als Wert einer Variablen — mit $(...) oder Backticks (`).

command-substitution.sh
#!/bin/bash
working_directory=$(pwd)
echo "Welcome, your working directory is $working_directory."
# veya doğrudan, değişken kullanmadan:
echo "Today is $(date)"
echo "You are $(whoami)"

num++ (post-increment) uses the current value first, THEN increments it. ++num (pre-increment) increments first, THEN uses the value. This subtle difference is a classic source of script bugs.

TRnum++ (post-increment) önce mevcut değeri kullanır, SONRA artırır. ++num (pre-increment) önce artırır, SONRA değeri kullanır. Bu ince fark script hatalarının klasik bir sebebidir.

DEnum++ (Post-Inkrement) verwendet zuerst den aktuellen Wert und erhöht ihn DANACH. ++num (Prä-Inkrement) erhöht zuerst und verwendet DANACH den Wert. Dieser feine Unterschied ist eine klassische Ursache für Skriptfehler.

sabit readonly Constants & $@ vs $* — Sabitler ve $@ ile $* farkı— Konstanten & $@ vs. $*

Two refinements that separate tidy scripts from fragile ones: readonly makes a variable a true constant (any later change is an error), and "$@" vs "$*" decide whether arguments stay separate words or collapse into one.

TRDerli toplu scriptleri kırılganlardan ayıran iki incelik: readonly, bir değişkeni gerçek bir sabite dönüştürür (sonradan her değişiklik hatadır); "$@" ile "$*" ise argümanların ayrı kelimeler mi kalacağına, yoksa tek kelimeye mi çökeceğine karar verir.

DEZwei Feinheiten, die ordentliche Skripte von fragilen trennen: readonly macht eine Variable zu einer echten Konstante (jede spätere Änderung ist ein Fehler), und "$@" vs. "$*" entscheiden, ob Argumente getrennte Wörter bleiben oder zu einem einzigen zusammenfallen.

SyntaxWith args a "b c" becomes
"$@"a and b c — separate words preserved (almost always what you want)
"$*"a b c — one single word
Sözdizimia "b c" argümanlarıyla sonuç

savunma Defensive Scripting: set -e, -u, -o pipefail — Savunmacı scripting— Defensives Scripting

By default bash keeps marching after an error — line 3 fails, line 4 runs anyway, often on garbage data. Three set options at the top of every serious script flip bash into "stop at the first problem" mode.

TRVarsayılan olarak bash bir hatadan sonra yürümeye devam eder — 3. satır başarısız olur, 4. satır yine de çalışır, çoğu zaman çöp veriyle. Her ciddi scriptin başındaki üç set seçeneği, bash'i "ilk sorunda dur" moduna geçirir.

DEStandardmäßig marschiert bash nach einem Fehler weiter — Zeile 3 scheitert, Zeile 4 läuft trotzdem, oft mit Mülldaten. Drei set-Optionen am Anfang jedes ernsthaften Skripts schalten bash in den Modus "beim ersten Problem anhalten".

OptionEffect
set -eExit immediately when any command fails
set -uUsing an unset variable is an error (catches typos!)
set -o pipefailA pipeline fails if ANY stage fails, not just the last
SeçenekEtkisi
set -eHerhangi bir komut başarısız olduğunda derhal çık
set -uTanımsız değişken kullanımı hatadır (yazım hatalarını yakalar!)
set -o pipefailPipeline, yalnızca sonuncusu değil, HERHANGİ bir aşaması başarısız olursa başarısız olur
OptionWirkung
set -eSofort beenden, wenn irgendein Befehl fehlschlägt
set -uVerwendung einer nicht gesetzten Variable ist ein Fehler (fängt Tippfehler!)
set -o pipefailEine Pipeline scheitert, wenn IRGENDEINE Stufe scheitert, nicht nur die letzte
GERÇEK LINUX'TA — SİMÜLASYONDA YOK
#!/bin/bash
set -euo pipefail        # üçü tek satırda — profesyonel script başlığı
cp "$KAYNAK" /yedek/     # KAYNAK tanımsızsa script BURADA durur,
rm "$KAYNAK"             # bu tehlikeli satıra asla ulaşmaz
💡 Tip: Memorize set -euo pipefail as one unit. In DevOps interviews and code reviews, its absence in a deploy script is a red flag.
💡 İpucu: set -euo pipefail'i tek parça olarak ezberle. DevOps mülakatlarında ve kod incelemelerinde bir deploy scriptinde bunun yokluğu kırmızı bayraktır.
💡 Hinweis: Merke dir set -euo pipefail als eine Einheit. In DevOps-Interviews und Code-Reviews ist ihr Fehlen in einem Deploy-Skript ein Warnsignal.

hataayıkla Debugging & Meaningful Exit Codes — Hata ayıklama ve anlamlı çıkış kodları— Debugging & aussagekräftige Exit-Codes

When a script misbehaves, don't guess — watch it. bash -x prints every line as it executes, with variables already expanded. And when your script ends, exit with a meaningful code so other tools can react.

TRBir script yaramazlık yaptığında tahmin etme — izle. bash -x, her satırı çalışırken, değişkenleri genişletilmiş haliyle basar. Ve scriptin bittiğinde, diğer araçlar tepki verebilsin diye anlamlı bir kodla çık.

DEWenn ein Skript sich falsch verhält, rate nicht — schau zu. bash -x gibt jede Zeile während der Ausführung aus, mit bereits expandierten Variablen. Und wenn dein Skript endet, beende es mit einem aussagekräftigen Code, damit andere Werkzeuge reagieren können.

GERÇEK LINUX'TA — SİMÜLASYONDA YOK
bash -x yedekle.sh          # scripti izleme modunda çalıştır: her satır '+' ile basılır
# script içinde bölgesel izleme:
set -x                      # buradan itibaren izlemeyi aç
tar -czf yedek.tar.gz /veri
set +x                      # izlemeyi kapat

# anlamlı çıkış kodları:
[ -d "/veri" ] || { echo "HATA: /veri yok"; exit 2; }
exit 0                      # her şey yolunda
💡 Tip: Convention: 0 = success, 1 = general error, 2 = wrong usage/missing input. Pick codes and document them — future-you will thank present-you.
💡 İpucu: Gelenek: 0 = başarı, 1 = genel hata, 2 = yanlış kullanım/eksik girdi. Kodları seç ve belgele — gelecekteki sen, şimdiki sana teşekkür edecek.
💡 Hinweis: Konvention: 0 = Erfolg, 1 = allgemeiner Fehler, 2 = falsche Verwendung/fehlende Eingabe. Wähle Codes und dokumentiere sie — dein zukünftiges Ich wird deinem jetzigen danken.
