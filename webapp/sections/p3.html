grup Group Management — Grup yönetimi— Gruppenverwaltung

Group membership is recorded in /etc/group. Groups let you give the same permissions to many users at once (e.g. everyone in "devops" can access certain files).

TRGrup üyelikleri /etc/group dosyasında tutulur. Gruplar sayesinde birçok kullanıcıya aynı anda aynı izinleri verebilirsin (örn. "devops" grubundaki herkes belirli dosyalara erişebilsin).

DEGruppenmitgliedschaften werden in /etc/group gespeichert. Gruppen erlauben es, vielen Benutzern gleichzeitig dieselben Rechte zu geben (z. B. kann jeder in der Gruppe "devops" auf bestimmte Dateien zugreifen).

A user can have one "primary" group and multiple "secondary" groups
Bir kullanıcının bir "birincil" grubu, birden çok "ikincil" grubu olabilir
Ein Benutzer kann eine "primäre" Gruppe und mehrere "sekundäre" Gruppen haben

uid UID & GID Conventions — UID ve GID kuralları— UID- & GID-Konventionen

Linux doesn't actually think in names — internally every user is a number (UID) and every group is a number (GID). The names in /etc/passwd are just labels mapped onto those numbers, and the number ranges follow a convention.

TRLinux aslında isimlerle düşünmez — içeride her kullanıcı bir sayıdır (UID), her grup bir sayıdır (GID). /etc/passwd içindeki isimler, bu sayılara eşlenmiş etiketlerden ibarettir ve sayı aralıkları bir kurala uyar.

DELinux denkt eigentlich nicht in Namen — intern ist jeder Benutzer eine Zahl (UID) und jede Gruppe eine Zahl (GID). Die Namen in /etc/passwd sind nur Etiketten, die auf diese Zahlen abgebildet werden, und die Zahlenbereiche folgen einer Konvention.

UID rangeWho
0root — the superuser. The number, not the name, grants the power
1 – 999System/service accounts (daemons like www-data, sshd)
1000+Regular human users (first user created = 1000, distro-dependent)
UID aralığıKim
0root — süper kullanıcı. Gücü isim değil, sayı verir
1 – 999Sistem/servis hesapları (www-data, sshd gibi daemonlar)
1000+Normal insan kullanıcılar (ilk oluşturulan = 1000, dağıtıma göre değişir)
UID-BereichWer
0root — der Superuser. Die Zahl, nicht der Name, verleiht die Macht
1 – 999System-/Dienstkonten (Daemons wie www-data, sshd)
1000+Normale menschliche Benutzer (erster Benutzer = 1000, distributionsabhängig)
TERMİNALDE ÇALIŞTIR
id                          # kendi UID, GID ve gruplarını gör
cat /etc/passwd             # user:x:1000:1000:… → 3. alan UID, 4. alan GID
💡 Tip: This is why deleting a user can leave "orphaned" files: the files still carry the old UID number, which now maps to no name.
💡 İpucu: Bir kullanıcıyı silmenin "sahipsiz" dosyalar bırakabilmesinin nedeni budur: dosyalar hâlâ eski UID sayısını taşır, ama o sayı artık hiçbir isme eşlenmez.
💡 Hinweis: Deshalb kann das Löschen eines Benutzers "verwaiste" Dateien hinterlassen: Die Dateien tragen noch die alte UID-Nummer, die jetzt auf keinen Namen mehr abgebildet wird.

chage Password Aging: chage — Şifre yaşlandırma— Passwort-Alterung

Corporate and school systems rarely let a password live forever. chage ("change age") controls when a password expires, how early the user is warned, and when an unused account is disabled — all stored in /etc/shadow.

TRKurumsal ve okul sistemleri bir şifrenin sonsuza dek yaşamasına nadiren izin verir. chage ("change age"), bir şifrenin ne zaman süresinin dolacağını, kullanıcının ne kadar önceden uyarılacağını ve kullanılmayan bir hesabın ne zaman devre dışı bırakılacağını kontrol eder — hepsi /etc/shadow'da saklanır.

DEFirmen- und Schulsysteme lassen ein Passwort selten ewig leben. chage ("change age") steuert, wann ein Passwort abläuft, wie früh der Benutzer gewarnt wird und wann ein ungenutztes Konto deaktiviert wird — alles gespeichert in /etc/shadow.

geçiş su vs su - vs sudo -i — Kullanıcı geçiş yolları— Wege des Benutzerwechsels

There are three common ways to "become" another user, and the difference is all about the environment you carry with you.

TRBaşka bir kullanıcı "olmanın" üç yaygın yolu vardır ve fark, tamamen yanında taşıdığın ortamla ilgilidir.

DEEs gibt drei gängige Wege, ein anderer Benutzer zu "werden", und der Unterschied liegt ganz in der Umgebung, die du mitnimmst.

CommandPassword askedEnvironment
su aliali's passwordKeeps YOUR current env — half-way state, error-prone
su - aliali's passwordFull clean login as ali (ali's HOME, PATH, .profile)
sudo -iYOUR passwordFull root login shell — the modern, logged, preferred way

su aliali'nin şifresiSENİN mevcut ortamın kalır — yarım durum, hataya açık
su - aliali'nin şifresiali olarak tam temiz giriş (ali'nin HOME, PATH, .profile'ı)
sudo -iSENİN şifrenTam root login shell — modern, loglanan, tercih edilen yol
BefehlAbgefragtes PasswortUmgebung

GERÇEK LINUX'TA — SİMÜLASYONDA YOK
sudo -i                # root'a tam login shell ile geç (tercih edilen)
whoami                 # → root
exit                   # kendi hesabına dön
💡 Tip: On servers, sudo is preferred over sharing the root password: every command is logged with WHO ran it, and access can be revoked per person.
💡 İpucu: Sunucularda sudo, root şifresini paylaşmaya tercih edilir: her komut KİMİN çalıştırdığı bilgisiyle loglanır ve erişim kişi bazında geri alınabilir.
💡 Hinweis: Auf Servern wird sudo dem Teilen des root-Passworts vorgezogen: Jeder Befehl wird mit der Info protokolliert, WER ihn ausgeführt hat, und der Zugriff kann pro Person entzogen werden.

sudoers The sudoers File & visudo — sudoers dosyası ve visudo— Die sudoers-Datei & visudo

Who may use sudo, and for which commands, is defined in /etc/sudoers. You must NEVER edit it with a normal editor — a single syntax error can lock everyone (including you) out of admin rights. visudo opens it safely and refuses to save broken syntax.

TRKimin sudo kullanabileceği ve hangi komutlar için kullanabileceği /etc/sudoers dosyasında tanımlanır. Bu dosyayı ASLA normal bir editörle düzenleme — tek bir sözdizimi hatası herkesi (sen dahil) yönetici yetkilerinin dışında bırakabilir. visudo dosyayı güvenle açar ve bozuk sözdizimini kaydetmeyi reddeder.

DEWer sudo benutzen darf und für welche Befehle, wird in /etc/sudoers definiert. Bearbeite sie NIEMALS mit einem normalen Editor — ein einziger Syntaxfehler kann alle (auch dich) von Admin-Rechten aussperren. visudo öffnet sie sicher und weigert sich, kaputte Syntax zu speichern.

GERÇEK LINUX'TA — SİMÜLASYONDA YOK
sudo visudo                       # sudoers'ı güvenli editörle aç
# örnek satırlar:
#   %sudo   ALL=(ALL:ALL) ALL      → sudo grubundaki herkes her şeyi yapabilir
#   ali  ALL=(ALL) /usr/bin/systemctl restart nginx
#        → ali SADECE nginx'i yeniden başlatabilir (dar yetki = güvenlik)
sudo usermod -aG sudo ali         # ali'yi sudo grubuna ekle (tam yetki)
💡 Tip: The professional pattern is the narrow rule: grant one exact command instead of blanket root. "Least privilege" is a core DevOps security principle.
💡 İpucu: Profesyonel desen dar kuraldır: her şeye root yetkisi yerine tek bir tam komut ver. "En az yetki" (least privilege), temel bir DevOps güvenlik ilkesidir.
💡 Hinweis: Das professionelle Muster ist die enge Regel: Gewähre einen exakten Befehl statt pauschalem root. "Least Privilege" ist ein zentrales DevOps-Sicherheitsprinzip.
