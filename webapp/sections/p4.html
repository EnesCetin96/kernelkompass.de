kavram What is a Package Manager? — Paket yöneticisi nedir?— Was ist ein Paketmanager?

Think of a package manager as an "office assistant" that fetches, installs, and organizes software for you — instead of manually downloading files from random websites, you just say "install git" and it handles dependencies, versions, and configuration.

TRPaket yöneticisini, senin için yazılım getirip kuran ve düzenleyen bir "ofis asistanı" gibi düşün — rastgele internet sitelerinden dosya indirip kurmak yerine sadece "git'i kur" dersin, o senin için bağımlılıkları (dependencies), sürümleri ve ayarları hallederder.

DEStell dir einen Paketmanager wie einen "Büroassistenten" vor, der Software für dich beschafft, installiert und organisiert — statt Dateien manuell von zufälligen Webseiten herunterzuladen, sagst du einfach "installiere git", und er kümmert sich um Abhängigkeiten, Versionen und Konfiguration.

Paket + bağımlılıkları otomatik bulunur, indirilir, kurulur
Paket + Abhängigkeiten werden automatisch gefunden, heruntergeladen, installiert

apt The Full APT Toolbox — APT'nin tam alet çantası— Der komplette APT-Werkzeugkasten

Install and remove are just the beginning. Professional Debian/Ubuntu administration uses the whole APT verb set — especially search and show before installing anything.

TRKurmak ve kaldırmak yalnızca başlangıçtır. Profesyonel Debian/Ubuntu yönetimi APT'nin tüm fiil setini kullanır — özellikle bir şey kurmadan önce search ve show.

DEInstallieren und Entfernen sind nur der Anfang. Professionelle Debian/Ubuntu-Administration nutzt das gesamte APT-Verbenset — besonders search und show, bevor man etwas installiert.

💡 Tip: update vs upgrade confuses everyone at first: update refreshes the CATALOG, upgrade installs the new versions. Always run them in that order.
💡 İpucu: update ile upgrade başta herkesi karıştırır: update KATALOĞU yeniler, upgrade yeni sürümleri kurar. Her zaman bu sırayla çalıştır.

depo Repositories: Where Packages Come From — Depolar: paketler nereden gelir— Repositories: Woher Pakete kommen

A package manager doesn't magically know about software — it reads a list of repositories: trusted servers that host packages plus an index. Each repo is cryptographically signed with a GPG key, so a tampered package is detected before it ever installs.

TRBir paket yöneticisi yazılımları sihirle bilmez — bir depo (repository) listesi okur: paketleri ve bir dizini barındıran güvenilir sunucular. Her depo bir GPG anahtarıyla kriptografik olarak imzalanır; böylece kurcalanmış bir paket daha kurulmadan tespit edilir.

DEEin Paketmanager kennt Software nicht durch Magie — er liest eine Liste von Repositories: vertrauenswürdige Server, die Pakete plus einen Index hosten. Jedes Repo ist mit einem GPG-Schlüssel kryptografisch signiert, sodass ein manipuliertes Paket erkannt wird, bevor es je installiert wird.

GERÇEK LINUX'TA — SİMÜLASYONDA YOK
cat /etc/apt/sources.list             # hangi depolardan besleniyorsun?

sudo add-apt-repository ppa:deadsnakes/ppa   # örnek: yeni depo ekle
sudo apt update                       # yeni deponun dizinini çek
💡 Tip: Only add repositories you trust. A repo can ship an update for ANY package on your system — full trust, full risk.
💡 İpucu: Yalnızca güvendiğin depoları ekle. Bir depo, sistemindeki HERHANGİ bir paket için güncelleme gönderebilir — tam güven, tam risk.
💡 Hinweis: Füge nur Repositories hinzu, denen du vertraust. Ein Repo kann ein Update für JEDES Paket auf deinem System ausliefern — volles Vertrauen, volles Risiko.

evrensel Universal Packages: Snap, Flatpak, AppImage — Evrensel paketler— Universelle Pakete

Classic .deb/.rpm packages are built per-distro. A newer generation of formats bundles the app with its dependencies so the same file runs on any distro — at the cost of larger downloads.

TRKlasik .deb/.rpm paketleri dağıtıma özel derlenir. Daha yeni nesil formatlar, uygulamayı bağımlılıklarıyla birlikte paketler; böylece aynı dosya her dağıtımda çalışır — bedeli daha büyük indirme boyutlarıdır.

DEKlassische .deb/.rpm-Pakete werden pro Distribution gebaut. Eine neuere Generation von Formaten bündelt die App mit ihren Abhängigkeiten, sodass dieselbe Datei auf jeder Distribution läuft — um den Preis größerer Downloads.

bakım Maintenance & Troubleshooting — Bakım ve sorun giderme— Wartung & Fehlerbehebung

Package systems occasionally jam: a download dies mid-install, disk fills with cached .deb files, or a second apt process holds the lock. These three rescue moves fix 90% of real-world package trouble.

TRPaket sistemleri ara sıra sıkışır: bir indirme kurulumun ortasında ölür, disk önbelleğe alınmış .deb dosyalarıyla dolar ya da ikinci bir apt süreci kilidi tutar. Bu üç kurtarma hamlesi, gerçek dünyadaki paket sorunlarının %90'ını çözer.

DEPaketsysteme verklemmen sich gelegentlich: Ein Download stirbt mitten in der Installation, die Festplatte füllt sich mit gecachten .deb-Dateien, oder ein zweiter apt-Prozess hält die Sperre. Diese drei Rettungszüge beheben 90 % der realen Paketprobleme.

GERÇEK LINUX'TA — SİMÜLASYONDA YOK
sudo apt clean                    # indirilen paket önbelleğini boşalt (yer aç)
sudo apt --fix-broken install     # yarım kalmış/bozuk bağımlılıkları onar
# "Could not get lock /var/lib/dpkg/lock-frontend" hatası:
#   → başka bir apt/güncelleyici çalışıyor demektir. Bitmesini bekle;
#     kilidi elle silmek SON çaredir ve yarıda kesilmiş işlem bırakabilir.
💡 Tip: The lock error is usually just Ubuntu's automatic updater running in the background — wait two minutes before assuming something is broken.
💡 İpucu: Kilit hatası genellikle Ubuntu'nun arka planda çalışan otomatik güncelleyicisidir — bir şeyin bozuk olduğunu varsaymadan önce iki dakika bekle.
💡 Hinweis: Der Sperrfehler ist meist nur Ubuntus automatischer Updater im Hintergrund — warte zwei Minuten, bevor du annimmst, dass etwas kaputt ist.
